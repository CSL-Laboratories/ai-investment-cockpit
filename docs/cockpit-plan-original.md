# Local AI Investment Cockpit Architecture

## Summary

Build a **Windows central-workstation system** that runs locally and uses authenticated Claude Code/Codex sessions as agent runtimes. The system is for personal/internal use, not a public product. It produces a morning investment brief, monitors market/news/portfolio changes during the day, escalates material events to stronger models, drafts trade proposals, and requires explicit human approval before any live order.

Default stack:

- **Host:** central Windows workstation, always awake during market hours.
- **Runtime:** TypeScript orchestrator plus Python data workers.
- **Storage:** SQLite for app state/audit logs, DuckDB/Parquet for market snapshots and research artifacts.
- **Agent runtimes:** Claude Code primary, Codex secondary/specialist.
- **Operator UI:** local web dashboard/PWA reachable from trusted devices, plus Claude Remote Control/Codex app for agent steering.
- **Broker mode:** paper trading first; live brokerage later behind approval gates.

## Key Changes / Implementation Plan

### 1. Local Control Plane

Create a local "AI ops host" with these services:

- `orchestrator`: schedules workflows, invokes agents, tracks usage budgets, owns job state.
- `agent-runner`: wraps `claude -p` and `codex exec`, supports JSON/streaming output, retry policy, timeout policy, and structured schemas.
- `market-ingestor`: pulls prices, holdings, filings, news, earnings calendar, macro calendar, and broker state.
- `risk-engine`: deterministic rules only; no LLM authority.
- `approval-center`: dashboard for human review, approval, rejection, notes, and kill switch.
- `audit-log`: append-only record of source data, prompts, model/runtime used, outputs, risk checks, approvals, order attempts, fills, and errors.

Implementation default:

- Use Windows Task Scheduler or a small local service to start the orchestrator at login.
- Use local-only HTTP on `127.0.0.1` by default.
- Expose to other devices only through a trusted tunnel/VPN or Claude Remote Control, not an unauthenticated LAN port.

### 2. Agent Runtime Harness

Use Claude Code and Codex as subprocess-backed agents.

Claude defaults:

- Fast triage: `claude -p --model haiku --output-format json --json-schema ...`
- Deep analysis: `claude -p --model opus --effort high --output-format json --json-schema ...`
- Autonomous bounded work: `claude -p "/goal <verifiable condition; stop after N turns>"`
- Ongoing session polling: `/loop` inside Claude Code for short-lived active monitoring.
- Cross-device continuity: `claude remote-control` for phone/browser steering.

Codex defaults:

- Deep research/coding/system maintenance: `codex exec --json --output-schema ...`
- Local app automation: Codex app automations/thread automations for recurring checks.
- Goal work: `/goal` for bounded implementation/research loops.
- SDK/app-server later only if CLI subprocess control becomes too limiting.

Agent runner contract:

- Every agent call must define: `runtime`, `model_or_alias`, `effort`, `input_refs`, `schema`, `timeout`, `max_turns`, `allowed_tools`, and `usage_budget`.
- Every response must be validated against JSON Schema before it can enter the decision pipeline.
- Failed validation triggers one repair attempt; second failure stores the raw output and marks the job `needs_human_review`.

### 3. Investment Workflow

Morning flow, weekdays before market open:

- Pull portfolio, watchlist, prior close, futures/indexes, overnight news, filings, earnings, macro events.
- Fast model classifies items into `ignore`, `watch`, `material`, or `urgent`.
- Deep model writes the morning brief only from classified source packets.
- Risk engine computes current exposure, concentration, open orders, planned entries/exits, and rule violations.
- Dashboard shows: brief, watchlist deltas, thesis changes, risk flags, proposed research tasks, and any draft trade ideas.

Intraday flow:

- Poll market/news/broker state at fixed intervals, with faster polling only for holdings, open orders, and active theses.
- Fast model triages deltas.
- Deep model is called only when a trigger fires: large price move, earnings surprise, filing/news hit, stop/target proximity, sector shock, or portfolio-risk threshold.
- `/loop` is allowed for short-lived active monitoring, such as "watch this event until the press conference ends," but durable market monitoring stays in the orchestrator.

Trade proposal flow:

- AI may draft a proposal with thesis, catalyst, intended holding period, invalidation condition, position size suggestion, and source references.
- Risk engine independently approves eligibility: symbol allowlist, max notional, max daily loss, buying power, asset class rules, stale quote checks, spread/slippage checks, and day-trading/margin constraints.
- Dashboard requires explicit approval before live execution.
- First implementation supports paper trading only. Live mode is added only after paper audit logs prove the workflow.

### 4. Data Interfaces

Minimum schemas:

- `MarketEvent`: symbol, source, timestamp, event_type, headline/summary, raw_ref, confidence, freshness.
- `PortfolioSnapshot`: timestamp, account, holdings, cash, buying_power, exposure, open_orders.
- `AgentJob`: runtime, prompt_template, input_refs, schema, status, usage_estimate, started_at, completed_at.
- `MorningBrief`: date, market_regime, portfolio_changes, watch_items, thesis_updates, risk_flags, proposed_actions.
- `TradeProposal`: symbol, side, asset_type, order_type, time_horizon, thesis, invalidation, sizing_basis, required_checks.
- `RiskDecision`: proposal_id, decision, failed_checks, warnings, max_allowed_notional, human_required.
- `ApprovalRecord`: proposal_id, user_decision, timestamp, device, notes, resulting_order_id.
- `AuditEntry`: immutable event stream for all material system actions.

Store raw inputs separately from model summaries so every memo can be traced back to source data.

### 5. Operator Experience

Dashboard views:

- Morning Brief
- Live Monitor
- Portfolio/Risk
- Trade Proposals
- Agent Jobs
- Audit Log
- Settings / Kill Switch

Notifications:

- Desktop notification for normal brief readiness.
- Mobile push or Remote Control notification for urgent events.
- Never notify for low-value noise unless explicitly enabled.

Controls:

- Global kill switch disables live order placement and cancels pending unapproved proposals.
- Mode selector: `read_only`, `paper`, `review_only_live`, `live_approved`.
- Live mode requires a daily unlock and expires after market close.
- Any agent uncertainty, schema failure, stale data, or failed risk check blocks live execution.

## Test Plan

- Unit test schema validation for every agent output type.
- Unit test risk rules: max notional, stale quote, allowlist, buying power, concentration, daily loss, and live-mode lock.
- Simulate morning brief generation from recorded market/news fixtures.
- Simulate intraday event escalation with mocked price/news deltas.
- Verify malformed Claude/Codex output cannot create a trade proposal.
- Verify paper-trade flow records full audit trail.
- Verify live execution path is unreachable unless mode, risk checks, and approval are all satisfied.
- Run an end-to-end dry run for one market day with no broker credentials and recorded data.
- Run a paper-trading replay for at least 2 weeks before considering live mode.

## Assumptions / Defaults

- This is a personal internal system for one operator.
- Central workstation is Windows and remains awake during market hours.
- Claude Code is the primary always-on runtime because it is already installed and authenticated with a Max subscription.
- Codex is used for secondary research, coding, app automation, and specialist loops.
- The first build does not place live trades.
- Paper trading is mandatory before live brokerage integration.
- AI never has final trading authority; deterministic risk checks and human approval are required.
- Exact model aliases are preferred over pinned model IDs for daily use; pinned IDs are reserved for reproducible research runs.
- The system optimizes subscription usage through filtering, caching, structured outputs, and escalation thresholds rather than constant deep-model polling.

## Findings, ordered by priority

### A7 — P1: Claude's declared no-tool boundary uses the wrong flag

**Location:** [runner.py:79](../../../app/agent_runner/runner.py:79), [tool_inspector.py:129](../../../app/agent_runner/tool_inspector.py:129).

The Claude command supplies `--allowedTools none`. The inspector accepts this sentinel as proof that the model has no tools. It does not require a restriction on available built-in tools, disable MCP discovery, or prevent ambient configuration from supplying capabilities.

Claude's official documentation distinguishes permission grants (`--allowedTools`) from available tools (`--tools`). Disabling built-ins requires an empty tool list; MCP tools need separate treatment. The installed Claude Code 2.1.252 help also identifies `--tools ""` as the way to disable built-ins. The audit reproduced the generated unsafe command passing the inspector; no model or exfiltration test was launched. [Claude CLI reference](https://code.claude.com/docs/en/cli-reference).

**Recommendation:** Define and require an explicit Claude capability-denial profile covering built-ins, MCP, and inherited configuration. Validate actual effective tool availability with harmless canaries in an isolated account; reject a missing or unsupported restriction. Do not treat a test of the same assumed flag string as an integration test of the CLI.

### A1 — P1: Mutable proposal sizing can bypass the final risk limit

**Location:** [paper_execution.py:253](../../../app/brokers/paper_execution.py:253), [paper_execution.py:367](../../../app/brokers/paper_execution.py:367), [proposals.py:310](../../../app/workflows/proposals.py:310).

The signed proposal event binds identifiers and generation lineage, but not its complete economic payload. `_fresh_risk` passes the fixed order quantity into cost verification, then passes the mutable original proposal into `evaluate`. These checks can therefore evaluate different sizes.

**Reproduction:** A stored one-share AAPL order at a $150 limit is correctly refused after an audited reduction of `max_notional` to $100. Editing only the unsigned proposal payload to quantity 0.1 and notional $15 makes approval and gateway submission succeed for the original **$150** order. The audit chain remains valid. Human confirmation is still required; this is a bypass of the deterministic cap, not a bypass of operator authentication. A keyless database writer is explicitly in the repository's threat model.

**Recommendation:** Construct final risk input from the authenticated canonical order tuple. Bind remaining proposal facts to a signed payload hash, validate their schema again, and require symbol, side, quantity, order type, price, and horizon consistency across the proposal, cost verdict, and submitted order. Reserve exposure using the same executable tuple.

### A2 — P1: Fresh broker equity does not refresh the loss limit

**Location:** [paper_execution.py:339](../../../app/brokers/paper_execution.py:339), [proposals.py:118](../../../app/workflows/proposals.py:118).

Approval fetches and signs a fresh account snapshot. The daily-loss risk check nevertheless uses cached `state.paper_performance`. The separate scheduled performance sample updates that object once per minute, so losses observed during approval are not necessarily enforced at submission.

**Reproduction:** Sample $100,000 equity, then make subsequent broker responses report $99,000. A new order submits despite the default $500 daily-loss limit. Reconstructing the signed ledger immediately afterward correctly reports a $1,000 drawdown, while the cached object still reports zero.

**Recommendation:** Reconstruct or incrementally advance verified performance through the fresh snapshot before granting order authority, then synchronously enforce the loss breaker. Bind freshness to the consumed audit sequence and trading day; refuse stale or unavailable performance.

### A6 — P2: An ordinary later filing is incorrectly treated as a merger amendment

**Location:** [merger_semantics.py:694](../../../app/strategies/merger_semantics.py:694).

Current-deal verification equates `current_accession != announcement_accession` with an amended transaction, then requires the current document to contain `amend`. Selection/calibration use a different rule based on actual merger-amendment language in the source set.

**Reproduction:** Valid announcement terms and exact dates pass. Adding a routine quarterly filing that changes no deal terms makes `_verify_deal` fail with `current deal amendment is not explicit in source`. This is a further availability defect in the source-set workflow, distinct from the already-fixed BUG-108 selection change.

**Recommendation:** Track filing recency and deal amendments as separate facts. Continue requiring complete reviewed sources, but use a shared transaction-specific amendment classifier. A normal filing must neither manufacture an amendment nor silently erase prior terms.

### A3 — P2: Non-visible HTML content can become merger authority

**Location:** [merger_semantics.py:171](../../../app/strategies/merger_semantics.py:171).

The semantic verifier strips HTML tags with a regular expression while retaining script/style bodies. Its separate text path does not use the protections already implemented for BUG-070 in the filing parser.

**Reproduction:** A body with no deal terms fails eligibility. Adding cash-merger example text inside a JSON `script` makes the same document yield an eligible, active $170 cash offer.

**Recommendation:** Share the hardened text extraction and exact byte-span provenance rules. Exclude code and hidden content, test quoted attributes and inline-XBRL cases, and retain the precise visible source spans behind every authority-bearing field.

### A4 — P2: Negated outcome statements are accepted as completed deals

**Location:** [merger_semantics.py:201](../../../app/strategies/merger_semantics.py:201), consumed by calibration at [merger_semantics.py:864](../../../app/strategies/merger_semantics.py:864).

The outcome parser screens modal/conditional words but does not establish assertion polarity or attribution.

**Reproduction:** `It is not true that the merger was completed.` is classified as `closed`. Because outcome labels feed completion probabilities, this is a calibration-integrity defect rather than just a display error.

**Recommendation:** Require affirmative, issuer/transaction-bound outcome assertions with scoped negation and attribution checks. Refuse ambiguous cases. Evaluate field precision against independently annotated unseen documents, not labels produced by the same parser.

### A5 — P2, future live integration: Live fills can invalidate paper performance

**Location:** [paper_performance.py:213](../../../app/brokers/paper_performance.py:213).

The reconstruction filters live submission intents out of paper performance but still processes their generic fill transitions. It then lacks the intended quantity and misreports the transition as an oversized fill.

**Reproduction:** A valid paper equity snapshot reconstructs successfully. Add a signed live-only intent/result and its filled transition; reconstruction fails with `fill exceeds signed order size`.

**Recommendation:** Carry execution scope through the entire reconstructed order lineage. Ignore positively identified non-paper orders while continuing to refuse unclassified or incomplete paper evidence. This is latent while live execution remains disabled, not an explanation for current soak behavior.

## Improvements with the highest expected value

1. **Close the authority gaps first.** Prioritize A7, A1, and A2, then the three semantic defects. Convert these reproduction assertions into regression tests of the desired refusal/correct behavior. Order-path changes need the repository's adversarial review and required platform matrix.
2. **Make research progress measurable.** Track discovery recall, parser precision and recall, refusal reasons, candidate yield, source age, and accepted held-out outcomes. A healthy process with zero admitted candidates should be visible as a blocked experiment, even when refusing is the correct safety action.
3. **Review the cohort design without changing live gates.** The manifest requires at least 30 distinct evaluation candidates on one selection date. Combined with the recorded absolute-head restriction, narrow forms, and exact current-target dates, the present process is struggling to generate evidence. Consider a separately reviewed protocol that prospectively witnesses individual admissions over time, preserves every admitted outcome, fixes the analysis in advance, and uses independent annotations. This is a proposed protocol change, not permission to seed a watchlist or lower existing acceptance standards. Do not conflate research-cohort eligibility with current-target trading eligibility.
4. **Measure economic value after costs and selection bias.** Compare awareness against a simple feed digest and record operator time saved and missed important events. Compare a frozen strategy against cash and a relevant merger-arbitrage baseline. Include failed/delisted deals, unresolved outcomes, financing, spread, impact, fees, and incremental subscriptions. Treat the Wilson/worst-observation estimate as a conservative heuristic whose assumptions require validation, not a guaranteed lower bound on economic return. Test cost-model sensitivity and regime concentration.
5. **Improve operational reproducibility.** Pin dependencies and CLI versions; record the tested source hash, interpreter, dependency manifest, and effective runtime profile with every soak. Run a second integration profile with the actual Discord dependency. Consolidate readiness into a small machine-readable status record, and derive summary documents from it. Profile full-ledger verification/reconstruction as data grows before adopting any trusted incremental checkpoint design.
6. **Test meaningful behavior as well as uptime.** Exercise restart recovery, broker response loss and idempotency, partial fills, out-of-band halt, stale quotes, changing limits, loss transitions, concurrent audit writes, and operator delivery. Keep synthetic reliability drills isolated from prospective strategy-performance evidence. A process running all weekend does not substitute for additional market observations.

Alpaca explicitly says paper simulation omits market impact, latency slippage, queue position, and several costs. It can also fill quantities larger than displayed liquidity. A green Alpaca paper P&L therefore cannot validate this project's execution-cost model on its own. [Alpaca paper-trading specification](https://docs.alpaca.markets/us/docs/paper-trading).

Before eventual broker integration, bind the margin policy to that broker's actual account regime. FINRA's new intraday-margin rules became effective June 4, 2026, but permit broker transition through October 20, 2027. The source's blanket post-PDT assumption is insufficient evidence that a particular account has transitioned. [FINRA guidance](https://syndication.finra.org/content/understanding-new-intraday-margin-requirements).

## Assessment of the premise

**Awareness and discipline: favorable.** Immutable source material, cited summaries, explicit human decisions, and deterministic risk controls address concrete personal-investing problems. The project is strongest when it helps its operator notice important information and follow a considered process. Measure that benefit directly; the repository's architecture is promising, but user-value evidence is still needed.

**Merger-arbitrage research: reasonable, economically unproven.** Fixed cash offers provide a concrete payoff to analyze, and the code correctly models completion, failure, and still-open outcomes. A spread alone is not expected profit. For illustration, paying $97 for a possible $100 payout with a $75 failure price produces only $0.50 expected profit at a hypothetical 90% completion probability, before costs and time value: `0.9 × $3 − 0.1 × $22`. A small probability error can remove that apparent edge.

**Autonomous profit engine: unsupported by the evidence.** Neither the test count, model agreement, nor uptime establishes alpha. The present bottlenecks are reliable semantic authority, an attainable prospective evaluation protocol, and an actual cost-adjusted track record. My recommendation is to continue the awareness product and bounded strategy research, fix the demonstrated defects, and judge progress by independently verified outcomes rather than additional architecture or continuous agent activity.
